# ユーザ設定

作成日: 2026-09-04

本書の「ユーザ」は導入先クライアント（組織）である。Salesforce の User レコード単位の製品設定は持たない。

## 0. 本書の位置づけ

値の意味、画面の出し方、保存時の拒否は次の正本のままである。本書へ移さない。

| 正本 | 範囲 |
| ---- | ---- |
| `仕様書_Core.md` | 契約・見積・受注・請求・入金。組織設定の項目と入口は第11章。商品は第3.1節。請求アカウントは第3.3節 |
| `仕様書_Accounting.md` | Accounting ON のときの仕訳。会計方針は第3.1節。会計マスタは第4章 |
| `共通基盤.md` | 権限、日付算法、契約横断、操作ログ |

本書が正とするのは次だけである。

- 初期設定の順番
- マスト／必要に応じて／Accounting ON のときだけ
- 単位（組織1件／マスタ行／Salesforce ユーザ／Salesforce 標準 Setup）
- 初期設定以降に変えてよいか。よい場合の影響（これから効くか、既存は書き換わるか）

導入ウィザードは持たない。入口は既存の組織設定タブ、標準画面、Setup である（Core 第11.6節）。

保持体の種類の寄せと差し替えはしない。Hierarchy カスタム設定でも、製品は組織既定だけを読み書きする（Core 第11.6節）。

## 1. 単位

| 単位 | 意味 | 例 |
| ---- | ---- | -- |
| 組織1件 | クライアント組織に高々1件。プロファイル・利用者・取引先・商品・契約による上書きは無い | 会計方針、見積書3択、既定サイクル数 |
| マスタ行 | 組織内で複数行。行ごとに値が違う | 商品、請求アカウント、勘定科目、コピー定義 |
| Salesforce ユーザ | 人への付与。製品の設定項目は持たない | 権限セット、権限セットグループ |
| Salesforce 標準 Setup | パッケージ外の組織設定。パッケージが読むものだけ本表に出す | 営業時間・休日、組織ワイドメール、OWD、ページレイアウト |

## 2. 初期設定の順番

この節の段が導入順の正である。同じ段の中は表の行順でよい。先の段が無いと、あとの段の検証や診断が足りないものを拾えない。

シードがある項目は、インストール直後から値がある。人が消したあとのアップグレードでは戻さない（Core 第11.6節。科目・手動仕訳シードは Accounting 第4.1節・第10.2節）。

| 段 | いつ | 中身 | 必須の見方 |
| -- | ---- | ---- | ---------- |
| 1 | パッケージを入れた直後 | 営業時間・休日、組織ワイドメール、Classic テキストメール、OWD／共有、権限セット（またはグループ）の付与 | メール送付と営業日補正を使うならマスト。権限はマスト |
| 2 | 業務ユーザの前 | 組織設定の帳票・送付、会社情報、契約（既定サイクル・見積有効期間・更新商談）、金額計算 | 帳票を使うなら会社情報はマスト。契約の数値はシードあり。金額計算はシードあり |
| 3 | 見積の前 | 商品マスタ（契約利用可と請求設定を含む）、請求アカウント、必要なら見積備考マスタ | 見積保存のマスト |
| 4 | 顧客項目が要るとき | カスタム項目、ウィザード／請求操作の追加項目定義、コピー定義、入力規則と Enforce 旗、ロック除外 | 必要に応じて。定義が壊れていれば見積・受注・確定が止まる |
| 5 | Accounting を使うと決めたとき、最初の請求確定より前 | 会計方針（ON と2方針と月次）、勘定科目、割当（必要ならテナント条件）、手動仕訳設定、会計タグルール | Accounting ON のときだけマスト（タグは任意） |
| 6 | 画面に出すとき | ページレイアウト、リストビュー、レポート、標準承認、ダミー商談 | 必要に応じて |
| 7 | 標準に無い自動化 | 更新商談の Flow／Apex、仕訳の自動 Lock バッチ | 必要に応じて。第7節 |
| 8 | 運用開始 | 最初の請求確定 | この操作で会計方針が固定する。OFF の確定でも OFF のまま固定する |

Accounting を使わない組織は段5を飛ばす。方針レコードは OFF のまま残し、最初の確定で OFF を固定する（Core 第11.8節、Accounting 第3.1節）。

| 追加項目コピー `FieldCopyDefinition__c` | 必要に応じて | マスタ行 | 変えてよい | 作成時の空欄だけ。既存レコードは動かない。壊れていれば見積新規・自動 Renew・受注・請求生成・分割・入出金・仕訳を止める。検証は組織設定から任意 | Core 第11.4.2節、Accounting 第3.1節 |

CMDT 変更後は cacheable 取得のため、当該 Apex を再デプロイする（Core 第11.4節）。

権限 21。Accounting ON で仕訳を出すときのマストは科目と割当。方針は組織設定。

| 設定 | 必須 | 単位 | 初期以降 | 影響 | 参照 |

## 4. 変更影響の横断

この節が「初期以降に変えたとき」の正である。

1. **会計方針だけ固定する。** 最初の請求確定（OFF の確定を含む）と同じトランザクションで固定する。固定後は画面・Apex・API・Data Loader から ON/OFF と方針項目を変えない。一括再構築は標準に無い（`UPDATE-003`）。
2. **マスタを直しても、すでにスナップショットした業務行は自動では動かない。** 商品→見積商品、請求アカウント→請求書、コピー元→コピー先、会社情報→発行済み PDF。戻す操作があるのは、未確定請求への「請求アカウントの内容を反映」だけである。
3. **金額計算と帳票3択は、これから行う計算・発行だけ新しい値を見る。** 保存済み金額の再計算と、保存済み見積値・PDF の一括消しは持たない。
4. **勘定科目割当の変更は初回生成だけ。** 同一生成単位の再生成は元のパターンと実勘定を維持する。
5. **タグルールの変更は次イベントから。** 仕訳本体は遡及しない。
6. **定義の不備は黙って飛ばさない。** 追加項目・コピー・必須会社情報・無い組織設定レコードは、実行時に止める。無い／空を既定へ落とさない。
7. **Salesforce ユーザへの権限付与はいつ変えてよい。** その人の入口が変わるだけで、他ユーザの業務結果は変えない。

## 5. 必須の早見（最初の見積まで）

段3までで見積保存できる最小である。

| もの | 無くてよいか |
| ---- | ------------ |
| 権限 03（と参照用 01 または 02） | 不可 |
| 組織設定の組織既定（帳票3択と契約数値） | 不可 |
| 契約利用可の商品（課金形態・請求設定・単価・単位・売上計上基準） | 不可 |
| 請求アカウント | 不可 |
| 商談（またはダミー商談） | 不可 |
| 会社情報 | 見積書3択が `使わない` なら後回し可 |
| 追加項目・コピー・Enforce | 無くてよい |
| Accounting ON と科目割当 | 無くてよい（OFF のまま） |

最初の請求確定の前に Accounting を ON にするなら、段5を確定より前に終える。確定したあと標準機能では ON に戻せない。

## 6. 画面に出さないが Setup にあるもの

組織設定の診断がリンクしないもの。効く／効かないは診断に書かない（Core 第11.6節）。

- コピー定義 0 件、商品 0 件、条件セット 0 件、タグルール 0 件、手動仕訳 0 件
- 組織ワイドメールの解決そのもの（保存と送付でエラーにする）
- Classic メール／Visualforce の種類の目次

## 7. 導入時に足してよい顧客実装（本表の外）

パッケージ標準の設定項目ではない。スイッチや入口だけが製品である。

| 実装 | 製品側 | 参照 |
| ---- | ------ | ---- |
| 更新商談を作るレコードトリガ Flow または Apex | 組織設定のスイッチとカウント。パッケージはテナントクラスを呼ばない。非同期・Queueable・Platform Event では受注に載せられない | Core 第11.5節 |
| 仕訳の自動 Lock バッチ | 手動 Lock だけが標準。人が選んだ行。未来日付も選べる。パッケージは外部送信成功を Lock 条件にしない | Accounting 第9.5節、Core 第7.7.3節 |
| 発行日を書くテナント自動化 | 発行日の自動設定は Core 標準必須ではない | Core 第11.1節 |
