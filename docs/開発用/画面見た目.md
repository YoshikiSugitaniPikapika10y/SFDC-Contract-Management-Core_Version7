# 画面見た目

作成日: 2026-09-08
更新日: 2026-09-11

業務ユーザに見えるカスタム画面の、見た目だけの正本である。業務結果の正は `仕様書_Core.md`、`仕様書_Accounting.md`、`共通基盤.md`、`ユーザ設定.md` である。本書を読んでも業務結果は変わらない。

作業手順は `開発ルール.md` である。切るのは `!DESIGN発掘`。着手は `!DESIGN実装`。本書の改正は利用者が書いたときだけである。機能仕様書へ転記しない。

## 0. 本書に書いてよいこと／書いてはいけないこと

書いてよい。余白、字の大きさ、見出しタグ、シェルの種類、一次／二次／破壊ボタンの置き、色のトークン、空と失敗の文の型（本文が文言を固定していないとき）、スピナーの置き場。

書いてはいけない。出すボタンの集合、権限、待ちを始める条件、保存単位、SOQL、出す行、ロック対象、帳票の中身、本文が固定した操作名と拒否文。本文が `Lock` と書いた語は画面も `Lock` である。

本文が区画・操作・ラベルの意味を既に書いていれば、追随は CHANGE または BUG である。DESIGN にしない。

## 1. 対象

対象は業務ユーザが見るパッケージのカスタム画面である。組織設定（権限 20）と会計マスタ（権限 21）と操作ログは、業務画面とシェルを揃えなくてよい。標準レコードページのハイライトと関連リストは Salesforce 標準に任せる。カスタム入口のラベルとボタン族だけ本書に従う。

## 2. シェル

フルページ（見積ウィザード、受注、請求ボード、契約横断）は、ページに `h1` を一つ、一次操作はヘッダ右またはフッタである。

請求ボードと横断右の請求書タイル（同じカード）は、入口と入力と実行を同じ作業面に置く。ヘッダ右にボタンだけ残して、入力を別タブや表の下やカード末尾へ置かない。

操作していないときのヘッダは、識別と操作と補助メタを重ねない。

- 識別は請求番号と宛名だけを見出しにする。届け方は見出しにしない。
- 届け方・請求日・入金予定・取引状態・送付日は1本の補助行に並べる。ラベルと値の組を縦に段積みしない。取引状態の下に同じ意味の注記を重ねない。
- 確定済みで明細を直せないことは取引状態で足りる。同じ意味の拒否文をヘッダ常時の段落にしない。拒むときの文面は仕様本文である。出す操作は変えない。

- 追加入力が無い操作（確定する、最新のPDFを見る）の一次はヘッダ右のままとする。
- 入力が要る操作（取消、請求書情報、PDF発行、送付）は、押したカードをその操作の作業面にする。理由・日付・帳票・実行はその面に揃える。明細表は出さない。他のヘッダ操作は隠す。戻ると元のタブに戻す。タブを明細へ送って左下へ入力を置かない。
- 表が作業そのもの（別の請求へ分ける、同一請求内分割）は、先の入力と実行を表の上に置く。表の下へ落とさない。
- 行の追加入力（入金取消、入金編集、手動仕訳取消、検収の逆仕訳基準日）は押した行の直下に置く。表全体の下とカード末尾へ置かない。
- 仕訳タブの手動仕訳登録は表の上に置く。登録ボタンは一つ。表の下とカード末尾へ置かない。表の上にスロット残高と会計タグの作業用表示は置かない。カードフッタのスロット残高とタグは残す。出す金額の集合はCore第8.10節。カードフッタは表と別面にする。表ヘッダのフィルタや金額列の下へ揃えて、列合計に見せない。
- 仕訳の複数Lock／Unlockは第5節（表の直上）。Unlock理由は表直上のバーである。

確認シェル（見積操作ハブ、アーカイブ、差し戻し、解約受注）は、見出し、結果の箇条書き、フッタ（キャンセル／実行）である。新しい確認画面もこの型にする。

Quick Action と `lightning-card` を新しく増やさない。既存の送付 Quick Action と契約サービス編集の card を寄せる作業は、手順と権限を変えずにシェルだけを確認系またはフルページへ寄せてよい。

## 3. 見出し

ページの題は `h1`。セクションは `h2`。カード内の区画は `h3`。見た目だけ大きい文字に見出しタグを使わない。フォームの題を `p` のままにしない。

## 4. 字と密度

本文と入力は 0.875rem 以上。補助（メタ、ピル、注記）は 0.75rem 以上。0.75rem 未満にしない。画面全体を `zoom` や `--*-density` で 1 未満にしない。請求ボードと横断右の請求書タイルは、溢れた文言を省略記号にせず期間と同じく折り返す。金額・数量・単価・日付・状態・ボタンは折り返さない。商品名を1行に収める縮小はしない。他の業務画面は、列が溢れたら文字を潰す前に列の優先度を落とすか省略記号と `title` にする。`overflow: clip` で桁やラベルを切らない。同一行に並べるフィルタは、ラベルの上端と入力の下端を行で揃える。項目の間隔は入力の高さが隠れない幅にする。チェックと行内ボタンは入力の高さに合わせる。請求ボード仕訳タブの表行は明細タブと同じ高さにし、セルの字はそれに合わせて小さくしてよい（0.75rem 未満にしない）。仕訳タブのフッタ数字を金額列に揃えて列合計に見せない。仕訳タブのメモ列はヘルプアイコンだけにする。ホバーでメモを参照する。入力はしない。入力と保存は行トグルの中に置く。保存ボタンは明細タブの端数ボタンと同じ大きさにする。仕訳タブの列順は選択、Lock、状態、計上日、イベント、借貸、金額、確認用、メモ。計上時期は計上日と同じセル。独立列にしない。借貸は1列（`AR 売掛金 / REV 売上`）。計上日・イベント・確認用は表ヘッダのその列でフィルタする。各フィルタは複数選べる。未選択は全件。選んだ候補の和で絞る。メニューに「すべて選択」と「すべて解除」を置く。すべて解除は未選択（全件）に戻す。確認用ヘッダの候補は明細（商品名）。確認用の文面では絞らない。計上日は月単位の入力。フィルタはヘッダ行に収め、表の上の別バーには置かない。確認用の幅はメモ列と状態列の余りから取る。状態列は「取消済」が1行で収まる幅に留める。字は切らない。余った幅は確認用・計上日・イベント・借貸へ回す。確認用は折り返す。ホバーの `title` は残してよい。借貸は潰さず、溢れたら折り返す。メモ列はアイコン幅に留める。何を残すか・候補は仕様本文（`CHANGE-980`。列順の先行は`CHANGE-978`）。行トグル（追加項目）はメモ列の左に、Lock 列と同じ細い列を置く。▶／▼ はその列だけ。イベントセルには置かない。金額列は桁区切りカンマ（例 `1,000`。負は `-1,000`）。円マークは付けない。保存値は変えない。

## 5. ボタン

一次（保存、確定、送付、受注する）は塗りつぶし一つまでをその面の主にする。二次（分ける、PDF、請求書情報）はゴースト。破壊（取消、アーカイブ、差し戻し）は一次の隣に同じ塗りつぶしで置かない。

タブはカード内の表示切替に使う。一次操作をタブにしない。

権限の無い操作は出さない（共通基盤第10章）。無いことを示すためにグレーの常時表示はしない。請求ボード仕訳タブのメモ保存は行トグルの中に置き、明細タブの端数ボタンと同じ大きさにする。表のメモ列に入力と保存は置かない。仕訳タブで表の直上に出す二次操作はゴースト。長い表では表ヘッダと同じ面で固定する。表の下には置かない。いつ出すかは仕様本文である。

## 6. 色と境界

状態色はエラー、警告、成功、処理中だけに使う。画面ごとのブランド色（見積青、請求緑）を増やさない。既存のアクセントは新規画面へコピーしない。枠は区画のためであり、装飾の色付きボーダーを増やさない。請求ボード仕訳タブの表ヘッダは、他の ops 表の muted より一段濃い灰にする。請求ボードと横断右の請求書タイル／カードの枠は、縁が分かるよう現行より少し濃くする。取消済みを含めて出したカードの見出しは muted にする。未確定・確定済みの緑は変えない。金額の取り消し線は付けない。会計タグのアイコンは、保存先が True のとき落ち着いたオレンジで活性にする。蛍光のグローは付けない。False のときは同じ位置に非活性（灰色）で残す。仕訳タブフッタのスロット略称は赤字。登場したスロットの 0 円は出し、0 でない金額より目立たなくする。

Lock 中の保存ボタンが赤になるのは共通基盤の契約横断が書いた結果である。DESIGN で消さない。

## 7. 画面に出す語

画面語は日本語の業務語である。フィルタや列のラベルに `FROM` / `TO` / `Version` を出さない。本文が英語の操作名を固定しているものは、その語のままにする（`Lock` / `Unlock`）。請求ボード版フィルタの「全Version」と `VersionN` は Core 第0.1節・第7.7.0節の固定文言であり、本節の `Version` 禁止の例外である。列ラベルは「版」。メールの From / To / Cc / Bcc はメール欄に限りそのままにしてよい。

内部向けの省略（「第二」「列モード」「出してよい操作」）を新しく置かない。既存は DESIGN で業務語に直してよい。ただし本文が固定した文言は変えない。

## 8. 空・権限なし・失敗

本文が文言を固定していないときの型は次である。

- 空: 「対象がありません。」
- 権限なし: 「この操作の権限がありません。」
- 失敗: 原因が分かる一文と、再試行できるときは再読み込み（または同等）を付ける

## 9. 待ちの見た目

いつ待たせるかは仕様本文である（Core第0.4節）。本書は置き場だけを定める。読むだけの一覧は操作を止めない。書き込み・発行・送付のあいだは対象ボタンを disable し、スピナーまたは「処理中」を対象面に出す。裏の面は動かさない。

## 10. 完了の見た目

いつ出すかと文面は仕様本文である（Core第0.3節）。本書は置き場だけを定める。完了は対象面の1文である。トーストは出さない。確認シェルは成功後すぐ閉じ、結果の箇条書きは残さない。実行前の結果箇条書き（第2節）は残す。
